## 2. Mermaid: parse and render

The validator only checks a chart's first line. Two further checks were added because a chart that fails to parse shows a red error box in the app instead of a diagram:

- **Parse** — `node tools/mermaid-check.mjs <checkout> content/lessons plan/base-lessons` evaluates every `chart={\`…\`}` template literal exactly as the MDX runtime does and parses it with the app's own `mermaid@12.3.0` under `jsdom`. Result: every chart parses (count and breakdown by type in `qa/METRICS.md`). One existing-lesson chart failed on the first run (`acid`: a semicolon inside a `Note over` line, which ends a Mermaid statement); it was fixed in the pack.
- **Render** — `node tools/render-check.mjs http://localhost:3111 content/lessons` drives headless Chrome through the DevTools protocol against the production build, loads every lesson page in a 16,000 px tall window so that lazily rendered charts are in view, and counts `.mermaid-render` nodes against `<Mermaid>` tags. Result: every chart rendered (log in `qa/render-check/render-check.txt`). A chart inside a collapsed `<DeepDive>` renders only when expanded (`tcp-udp`), which is the component's intended behaviour. Final run against the 143-lesson production build on 2026-11-22: 171 charts parsed with 0 failures (158 in `content/lessons/`, the rest the base copies of the improved existing lessons), 143 pages rendered, 142 with every chart drawn and `tcp-udp` pending for the reason above (`qa/render-check/mermaid-check.txt`, `qa/render-check/render-check.txt`, `qa/render-check/check-output.txt`). Visual evidence for the approved `classDiagram` support: `qa/render-check/class-relationships-uml.png`, a full-page screenshot of the production build in the dark theme showing the class diagram and the sequence diagram.

Two earlier approaches were discarded: `--dump-dom` with a virtual time budget never fires the component's `IntersectionObserver`, and `--screenshot` hangs against the dev server; the DevTools checker needs only Node 22+ and a Chrome binary.

## 5. Data-file generation

`plan/merge_bundles.py` is idempotent: running it twice produces byte-identical `data/` and `content/` output. It refuses a bundle whose `meta.json` lacks a required field, whose quiz has other than four options, or whose `moduleId` or `level` is outside the closed unions. Review hashes of every reviewed bundle are kept in `plan/review-hashes.json` so that a later edit to a reviewed lesson is detectable.
