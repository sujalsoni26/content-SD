The best revision for a case study is not rereading it: close the lesson, write the requirements from memory, draw the class diagram and the main sequence, and only then compare. If the diagram came out different, ask whether yours still keeps every responsibility in one place and every invariant behind a method (see [OOP pillars](/learn/oop-pillars)); a different design that does both is not wrong. Redo one problem a week, starting with the [parking lot](/learn/lld-parking-lot), and the fourteen problems become one habit.
